**Combined Master:** User App + Vendor App + Admin Website

This is the single master document for AARUVO's three main product surfaces.

```text

  ↓

  ↓

  ↓
Products / Stores / Outcome Plan
  ↓

  ↓

  ↓

  ↓

  ↓

ADMIN WEBSITE
oversees Merchants + Users + Catalogue + Orders + Outcomes +

Risk + AI Quality + Trust + Finance + Growth
```

## Shared principles

- AI Mode + Manual Mode must coexist.
- AI should reduce work, but core operations must continue manually if AI is unavailable.
- Important actions require appropriate confirmation and permissions.
- DIGITAL / PREPAID ONLY — COD NOT SUPPORTED.
- Trust, transparency, explainability and user control are core.
- AARUVO is multi-category: grocery, food, electronics, fashion, wholesale, nearby small shops, large stores and future eligible categories.
- Voice-first accessibility is important for low-literacy customers and merchants.
- Provider integrations should remain replaceable where practical.

# 1. CORE VISION

AARUVO User App should not feel like only a grocery app, food app or normal shopping marketplace.

It should feel like:

> **“Tell AARUVO what you need or what you want to achieve. AARUVO helps you find, understand, prepare, buy, receive and use it.”**

The app must support both AI Mode and Manual Mode.

# 40A. SMART NEARBY-STORE RESCUE WHEN ORDER ITEM FAILS

AARUVO should not immediately end the customer's intent just because one merchant cannot fulfil an ordered item.

Examples:

- merchant rejects an item,
- product becomes unavailable after payment,
- stock mismatch is discovered,
- merchant cancels because the item is unavailable,
- an approved substitution cannot be fulfilled.

Instead of showing only:

> “Item cancelled.”

AARUVO should move into **Commerce Rescue Mode**.

---

# 40B. APOLOGY + CLEAR EXPLANATION

User should receive a simple friendly message/voice response:

> “Sorry, neenga order panna indha product current shop-la available illa.”

Then immediately:

> “Aana nearby-la vera shop-la same/suitable product available irukku. Paakanuma?”

Do not blame the merchant without confirmed evidence.

Show exact reason only when known.

---

# 40C. NEARBY REPLACEMENT SEARCH

AARUVO automatically searches serviceable nearby stores for:

1. Exact same SKU/product
2. Same brand + same size/variant
3. Equivalent product if exact product is unavailable
4. Best-fit alternative only when user permits substitution

Ranking can consider:

- exact-match confidence,
- price,
- distance,
- ETA,
- stock confidence,
- merchant reliability,
- delivery feasibility,
- user's saved substitution preference.

---

# 40D. USER APPROVAL BEFORE RE-ORDER

**Nearby match found**

- Product
- Store
- Distance

- Difference from original item

Actions:

- **Approve Nearby Store**

Voice options:

> “Approve pannu.”

> “Cheaper shop kaatu.”

# 40E. PAYMENT / PRICE DIFFERENCE HANDLING

If nearby rescue changes the amount, AARUVO must show it before confirmation.

## Same or Lower Price

System can show the difference and process according to platform/payment rules after explicit user approval.

## Higher Price

Never charge extra silently.

Show:

> “Nearby store-la price ₹18 adhigam. Continue panna additional payment approval thevai.”

User explicitly approves the extra digital payment.

## Lower Price / Refund Difference

Show expected refund/adjustment clearly according to payment/refund rules.

---

# 40F. DELIVERY RESCUE OPTIONS

Depending on order state, AARUVO may offer:

### Option A — Add Replacement to Existing Fulfilment
If operationally possible.

### Option B — Create Linked Rescue Order
A second nearby merchant fulfils the missing item.

### Option C — Deliver Original Available Items + Refund Missing Item

### Option D — Cancel Full Order
Only if user chooses and policy permits.

The UI should clearly show if a second rider/delivery fee or later ETA is involved.

---

# 40G. OUTCOME-AWARE RESCUE

For CookReady or other outcome baskets, rescue should consider whether the missing item is essential.

Example:

Brownie plan needs cocoa powder.

If original store cannot fulfil it, AI says:

> “Cocoa powder brownie-ku important item. 1.2 km away-la same product available. ₹10 price difference. Add pannalama?”

If an item is optional:

> “Indha item optional. Remove pannalum brownie complete panna mudiyum.”

This helps the user complete the outcome, not merely protect the original order.

---

# 40J. RESCUE TRUST RULES

AARUVO must never:

- silently move an order to another merchant,
- silently charge a price difference,
- claim an alternative is identical when it is not,
- hide an extra delivery charge,
- hide a longer ETA,
- force a replacement when user wants refund/cancel,
- expose unnecessary merchant blame to the user,
- recommend unavailable stock as confirmed availability.

Always use:

**Detect Failure -> Apologize -> Search Nearby -> Explain Difference -> User Approves -> Payment Adjustment if Needed -> Fulfil -> Track**

---

# 40K. RESCUE LEARNING LOOP

After completion, AARUVO should learn operationally from rescue events:

- merchant stock mismatch,
- repeatedly unavailable SKU,
- locality supply gap,
- replacement acceptance rate,
- price difference,
- extra delivery impact,
- outcome completion impact.

This can improve future merchant ranking, stock alerts, demand planning and catalogue quality without exposing private user context.
